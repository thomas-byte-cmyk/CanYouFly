# Bilan du projet CAN YOU FLY? — 14/11/2026

## 1. Le projet en bref
- **Jeu** : arcade 2D cartoon HTML5 pour **Poki**. Boucle visée : construire un avion → voler de ville en ville → atterrir ou crasher → récompense → débloquer → reconstruire.
- **Nom** : « CAN YOU FLY? » est un nom de code ; le nom final sera choisi en Phase 4.
- **Repository** : https://github.com/thomas-byte-cmyk/CanYouFly. Il est **public** (choix du porteur du projet, pour GitHub Pages). La branche par défaut est `main`.
- **Jeu en ligne** : https://thomas-byte-cmyk.github.io/CanYouFly/ (version 0.5, déployée automatiquement à chaque fusion dans `main`).
- **Pilotage** : le chef de projet est une IA (Claude Code). Le porteur du projet valide les grandes décisions. 4 agents spécialisés (dev, game design et direction artistique, marketing, économie) ont rédigé la conception en Phase 1.
- **Testeurs** : le porteur du projet et son fils (12 ans et plus).

## 3. Ce qui existe dans le jeu (v0.5)
- **Une étape** construite à la main : Paris → Reims (tutoriel). Elle contient une piste de départ, des champs, des vignes, une forêt, la Marne (eau) et un champ de secours.
- **À l'arrivée**, 3 zones balisées par des drapeaux : Grand champ ★, Piste de Reims ★★, Parc de la cathédrale ★★★ (très difficile, jamais réussi par le pilote robot).
- **Commande à un doigt** :
  - doigt à droite (ou Espace / ↑ / clic) = monter ;
  - doigt à gauche (ou ↓) = piquer ;
  - rien = descente douce ;
  - arrondi automatique près du sol ;
  - gaz automatiques ;
  - volets et aérofreins automatiques en approche.
- **Ancien pilotage** (manche + gaz) : disponible avec `?controls=stick` à la fin de l'adresse.
- **Aides à l'atterrissage** :
  - ombre de l'avion au sol ;
  - trajectoire prévue « si je relâche maintenant », avec le résultat annoncé (PARFAIT / BON / BRUTAL / CRASH / PLOUF) ;
  - liste des zones avec leur distance ;
  - indicateur de descente.
- **Résultats** : PERFECT, GOOD, ROUGH, CRASH ou WATER CRASH.
  - Une étape est validée dès que l'avion s'arrête dans une zone d'arrivée hors de l'eau, même après un crash.
  - La qualité de l'atterrissage donne de 1 à 3 étoiles et des Boulons (la monnaie).
- **En croisière** :
  - 3 séries d'anneaux, dont un anneau « boost » ;
  - 21 Boulons à ramasser ;
  - du vent arrière, une zone de rafales et 2 ascendances ;
  - une montgolfière et des oiseaux : les heurter ralentit l'avion, sans provoquer de crash.
- **3 avions au choix** (avant-goût du hangar) :
  - L'Albatros : facile, plane loin ;
  - Le Coucou : moyen, équilibré ;
  - La Fusée : difficile, rapide, atterrit vite et consomme beaucoup.
  - Leur comportement en vol (montée, descente, vitesses, réactivité, autonomie) est **calculé à partir de leurs pièces**, et l'écran de choix l'affiche en 6 barres.
- **Pip, le pilote** : visible dans le cockpit, avec des expressions et des états après le vol (décoiffé, sonné et noirci, trempé…). Ses cosmétiques restent toujours affichés.
- **Écran de résultats** : récit du trajet, phrase drôle, statistiques, Boulons gagnés, conseil ciblé, boutons « Revoler » et « Changer d'avion ».
- **Graphismes** : formes simples, en attendant les vrais dessins.
- **Absents pour l'instant** : son, sauvegarde (les Boulons sont perdus en rechargeant la page), hangar, SDK Poki.

## 5. Décisions validées (détail : `DECISIONS.md`)
- **D1** : construction par emplacements (fuselage + 10 emplacements, aile en 3 positions), pas de construction libre.
- **D2** : premier vol sans construction, avec l'avion « Le Coucou ».
- **D3** : remplacée par D16 (commande à un doigt). Le mode paysage est conservé.
- **D4** : pas d'améliorations de caractéristiques ; on progresse en débloquant des pièces *différentes*.
- **D5** : étape validée dès l'arrêt dans la zone d'arrivée, hors de l'eau ; étoiles selon la qualité.
- **D6** : parcours en 8 étapes : Paris → Reims (tutoriel) → Bruxelles → Amsterdam → Londres → Berlin → Rome → Athènes → Istanbul.
- **D7** : flotteurs après le MVP.
- **D8** : direction artistique « Atelier du Dimanche » (affiches de voyage rétro, avions bricolés) ; pilote « Pip », sans genre marqué.
- **D9** : **zéro budget** pour l'instant (packs gratuits, IA, production maison). On investira seulement si le jeu reçoit de bons retours.
- **D10** : une seule monnaie, les « Boulons » ; pub entre deux parties seulement au clic sur « Revoler » ; 2 pubs récompensées facultatives (×2 gains, essai d'une pièce).
- **D11** : durée du MVP de 1 h 30 à 2 h 30, sans pub.
- **D12** : cible 8–16 ans et familles, mobile en priorité, français + anglais.
- **D13** : nom final choisi en Phase 4.
- **D14** : jalon « Sensation de vol » avant le reste.
- **D15** : candidater tôt à Poki for Developers (bêta fermée) ; exclusivité web acceptée.
- **D16** : commande à un doigt par défaut.

## 6. Technique
- **Outils** : Phaser 3.90 + TypeScript + Vite ; tests avec Vitest ; vérifications GitHub Actions (tests, compilation, poids du jeu ≤ 4 Mo — actuellement environ 1,5 Mo) ; déploiement GitHub Pages.
- **Physique** : écrite pour le jeu, calculée 60 fois par seconde, séparée de l'affichage (`src/sim/`). On peut la tester sans navigateur.
- **Données** : toutes les valeurs de jeu sont dans des fichiers JSON (`src/data/` : avions, réglages, surfaces, seuils d'atterrissage, étape).
- **Outils de réglage sans affichage** (`scripts/`) : simulation, pilote robot (vérifie que chaque avion peut réussir l'étape), mesure de la réactivité, rapport sur les avions.
- **Tests** : 39 tests automatiques. Ils vérifient par exemple qu'aucun avion n'est meilleur que les autres partout, et que chaque avion peut finir l'étape.
- **Organisation Git** : chaque version est poussée sur la branche de travail, puis fusionnée dans `main` par Pull Request (PR #19 à #23).
- **Suivi** : 18 issues (#1 à #18) ; libellés par domaine, priorité, type et phase.
- **Documents** : 16 documents de conception dans `docs/`, plus `README`, `PROJECT_STATUS`, `ROADMAP`, `DECISIONS` et `CHANGELOG` à la racine.

## 7. Points ouverts et risques
- **Le hangar n'existe pas encore**, alors que c'est le cœur de la promesse (issues #9 et #10).
- **Équilibre aide / défi** : les aides (coussin près du sol, arrondi automatique, aérofreins) rendent le jeu accessible, mais peut-être trop facile pour les 12 ans et plus.
- **Parc ★★★** : à valider en jeu, il est peut-être impossible.
- **Graphismes sans budget** : principal risque visuel du projet.
- **Pas de son ni de sauvegarde.**
- **Règles Poki** : jamais lues en entier, car le réseau de l'IA bloque `poki.com` (issue #3).
- **Accès à Poki for Developers** : non garanti (issue #17).
- **Téléphones très allongés** : bandes noires sur les côtés.

## 8. Prochaine étape proposée par le chef de projet : Phase 2b (prototype complet)
1. **Hangar par emplacements** :
   - pièces installées par un tap, glisser-déposer en bonus ;

2. **Catalogue d'environ 24 pièces** réparties en 12 catégories, chacune avec avantages et défauts. Le calcul du comportement en vol existe déjà.
3. **Pip personnalisable** (3 à 4 cosmétiques) et dégâts visibles sur l'avion.
4. **Premiers sons** : 10 à 15 bruitages libres de droits.
5. **Sauvegarde locale.**
6. **2e étape** : Reims → Bruxelles.
7. **Point « go / no-go »** : est-ce amusant ?
